# EINEIRO — дополнение к Silent Run 2.0

## Рекламный бюджет платформы и запрет рекламы сэллеров

**Версия:** 1.0  
**Дата:** 14 сентября 2026  
**Статус:** CANONICAL / P0 / ОБЯЗАТЕЛЬНО  
**Родительское ТЗ:** `EINEIRO_Silent_Run_and_Platform_Intelligence_Spec_v2.md`

Это дополнение является обязательной частью Silent Run 2.0. При противоречии с более ранними решениями действуют правила этого документа.

## 1. Цель

На этапе Silent Run EINEIRO проверяет собственный цикл привлечения покупателей и качество платформы. Рекламные возможности сэллеров не продаются, не субсидируются и не включаются.

Разрешён только один рекламный контур:

`бюджет EINEIRO → реклама EINEIRO → вход в EINEIRO → намерение пользователя → честная выдача`.

## 2. Неизменные правила

1. Используется только рекламный бюджет платформы EINEIRO.
2. Рекламируется только EINEIRO как приложение, Market, камера, общий пользовательский сценарий, категория или нейтральная тематическая сцена.
3. Пользователи и сэллеры не могут подключать собственные рекламные кабинеты.
4. Пользователи и сэллеры не могут создавать, запускать, изменять или оплачивать рекламные кампании через EINEIRO.
5. Бюджет платформы нельзя использовать для продвижения конкретного сэллера, магазина, товара, объявления или карточки.
6. Сэллер не может купить преимущество в витрине, поиске, рекомендациях или выдаче.
7. После появления намерения пользователя результат определяется релевантностью, наличием, качеством и правилами Market, а не рекламным бюджетом.
8. Комиссия за продажу остаётся 0%.
9. Платное продвижение, платная витрина и рекламные услуги для сэллеров выключены.
10. Отключение режима Silent Run само по себе не включает рекламные кабинеты сэллеров и товарную рекламу. Для этого потребуется отдельное решение, отдельный флаг, юридическая проверка и новый релиз.

## 3. Разрешённые цели кампаний платформы

- установка приложения EINEIRO;
- открытие приложения или веб-версии;
- открытие главной камеры;
- демонстрация сценария «Покажи, что хочешь»;
- вход в категорию Market;
- вход в нейтральную сцену категории;
- возврат пользователя в EINEIRO;
- проверка нового креатива, аудитории или канала;
- проверка стоимости успешного намерения и полученного результата.

Реклама категории не должна закреплять пользователя за конкретным сэллером или объявлением.

## 4. Запрещённые цели

- карточка конкретного товара;
- объявление конкретного сэллера;
- витрина конкретного магазина;
- увеличение продаж выбранного сэллера за счёт бюджета EINEIRO;
- оплата рекламы сэллера из общего бюджета платформы;
- приём денег за продвижение;
- скрытая приоритизация рекламируемого товара;
- передача рекламному кабинету необязательных персональных данных;
- автоматический запуск рекламы без лимитов и аварийной остановки.

Допускается показать товар внутри демонстрационного креатива EINEIRO только как иллюстрацию сценария. Такой товар не получает приоритета после перехода и не становится целевой карточкой кампании.

## 5. Разделение контуров

Каждая кампания обязана иметь:

- `campaign_scope`: `PLATFORM` или `SELLER`;
- `funding_source`: `EINEIRO_BUDGET` или `SELLER_AD_ACCOUNT`;
- `destination_type`: `APP_INSTALL`, `APP_OPEN`, `CAMERA`, `CATEGORY`, `SCENE`, `OFFER`;
- `organization_id`;
- `campaign_id`;
- `creative_id`;
- `attribution_id`;
- лимиты бюджета;
- состояние аварийной остановки;
- идентификатор релиза и эксперимента.

В Silent Run принимается только сочетание:

`campaign_scope=PLATFORM`  
`funding_source=EINEIRO_BUDGET`  
`destination_type ∈ APP_INSTALL | APP_OPEN | CAMERA | CATEGORY | SCENE`.

Любая другая комбинация отклоняется сервером.

## 6. Обязательные флаги

- `SILENT_RUN=true`;
- `PLATFORM_ACQUISITION_ENABLED=true`;
- `SELLER_AD_CONNECTORS_ENABLED=false`;
- `SELLER_CAMPAIGNS_ENABLED=false`;
- `PLATFORM_BUDGET_CAN_PROMOTE_OFFERS=false`;
- `SPONSORED_SHOWCASE_ENABLED=false`;
- `COMMERCIAL_PAYMENTS_ENABLED=false`.

Изменение одного флага не должно автоматически изменять остальные.

## 7. Защита интерфейса и API

### Интерфейс сэллера

В EINEIRO Business отсутствуют или заблокированы:

- подключение рекламного кабинета;
- ввод ключей и токенов рекламных систем;
- создание рекламной кампании;
- выбор товара для рекламы;
- пополнение рекламного бюджета;
- запуск и остановка рекламы;
- запрос субсидирования из бюджета EINEIRO.

Нельзя ограничиваться скрытием кнопок. Соответствующие серверные операции также обязаны возвращать отказ Silent Run.

### Админка платформы

В EINEIRO Admin создаётся раздел «Привлечение EINEIRO»:

- кампании;
- креативы;
- каналы;
- аудитории;
- эксперименты;
- атрибуция;
- бюджет;
- аварийная остановка.

Доступ имеют только разрешённые роли платформы. Компания-сэллер не получает доступ к этому разделу.

## 8. Правила бюджета

- отдельный дневной и месячный лимит;
- максимальная стоимость успешного намерения;
- максимальная стоимость возвращённого пользователя;
- лимит на один эксперимент;
- лимит изменения бюджета за одно решение;
- обязательное подтверждение изменения выше автономного порога;
- аварийная остановка вручную и автоматически;
- запрет перераспределения бюджета на товарные кампании;
- полный журнал решений и изменений.

## 9. Атрибуция и «Бортовой самописец»

Обязательная цепочка:

`показ → нажатие → открытие EINEIRO → камера → намерение → результат → товар → сохранение/переход к сэллеру → возврат`.

Хранить:

- рекламный канал;
- кампанию;
- креатив;
- аудиторию и вариант эксперимента;
- стоимость;
- обезличенную сессию;
- намерение;
- факт получения результата;
- время до результата;
- дальнейшее действие;
- возврат D1/D7/D30;
- релиз и активные флаги.

Не хранить непрерывное видео, непрерывную запись микрофона, биометрические шаблоны и необязательные персональные данные.

Основные показатели:

- стоимость открытия EINEIRO;
- стоимость завершённого захвата;
- стоимость созданного намерения;
- стоимость успешного результата;
- доля запросов без результата;
- переход из результата в карточку;
- сохранение;
- переход к сэллеру;
- возврат D1/D7/D30;
- вклад кампании в обслуженный спрос.

## 10. Этапы допуска трафика

- T0 — внутренние проверки;
- T1 — 10–30 контролируемых пользователей;
- T2 — 50–100 новых пользователей в сутки;
- T3 — 300–500 в сутки;
- T4 — 1 000–3 000 в сутки;
- T5 — масштабирование.

Переход между этапами разрешён только после прохождения порогов качества Silent Run. При P0/P1 реклама останавливается, проблемный флаг выключается, базовый сценарий сохраняется.

## 11. Критерии приёмки

- [ ] сэллер не может подключить рекламный кабинет через интерфейс;
- [ ] сэллер не может подключить рекламный кабинет через API;
- [ ] сэллер не может создать или запустить кампанию;
- [ ] бюджет EINEIRO нельзя направить на конкретный товар или сэллера;
- [ ] платёж за продвижение создать невозможно;
- [ ] платная витрина выключена;
- [ ] кампания платформы ведёт только в разрешённые точки EINEIRO;
- [ ] рекламный переход связан с намерением и результатом;
- [ ] выдача после намерения не зависит от рекламного бюджета;
- [ ] лимиты и аварийная остановка работают;
- [ ] каждое изменение записывается в журнал аудита;
- [ ] снятие Silent Run не включает рекламу сэллеров автоматически;
- [ ] тесты проверяют интерфейс, API, бюджет, атрибуцию и отрицательные сценарии.

## 12. Выход из Silent Run

Рекламные кабинеты сэллеров могут появиться только после отдельного решения владельца платформы и выполнения всех условий:

1. юридическая модель рекламной услуги проверена;
2. определено, кто принимает деньги и несёт ответственность;
3. создан отдельный бюджетный контур сэллера;
4. подтверждено согласие на подключение кабинета;
5. обеспечены изоляция компаний и отзыв токенов;
6. добавлены отдельные флаги и права;
7. проведены тесты и контролируемый запуск;
8. выпущен отдельный релиз.

До выполнения всех восьми условий режим рекламы сэллеров остаётся технически недоступным.
