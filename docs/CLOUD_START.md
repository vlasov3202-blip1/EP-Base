# EINEIRO cloud startup

Use the existing checkout `/workspace/EP-Base`. The product is EINEIRO; EP-Base is the historical repository name. Preserve user changes and working data. Do not create a worktree unless requested. Read `AGENTS.md`, `PRODUCT.md`, `EINEIRO_CANONICAL.md` and the accepted Silent Run addendum before making product decisions.

The repository vendors 33 skills under `.agents/skills/<name>/SKILL.md`; their inventory, source commits, licenses and hashes are in `docs/skills-lock.json`. Read `docs/SKILLS.md` to choose the relevant skill, then read its SKILL.md and only needed references, relative to that skill's directory. Spec Kit and project migrations follow the same existing product contracts. Only three Superpowers skills are present. Do not install any other skills, plugins, hooks or packages at startup.

Run `bash scripts/cloud-skills-setup.sh` from the checkout (or by its absolute path) to check existing files without installation, network or database access. Skills are instructions; Specify, Playwright and Impeccable engine caches are optional separate tools. The setup script deliberately does not run npm, build the application or download engines. Use actual package scripts only for a requested application task and verify dependencies then.

Native Codex sessions must start with `/workspace/EP-Base` as their working directory. The session's initial `/workspace` directory is above the repository and does not establish discovery of its child `.agents/skills`. A shell cd alone is not evidence that a running session's skill catalogue changed. A nested Codex 0.159.2 process in the onboarding instance cannot create its installation_id under the read-only service profile; this failed before native loading and before a fresh model session. Do not change HOME/CODEX_HOME, protected directories, mounts or sandbox policy to work around this. If native discovery is unavailable, explicitly read the relevant local skill and report that fallback separately. Never report a hash check or manual file read as native discovery.

For a new-task verification follow `docs/CLOUD_SKILLS.md`. Confirm the restored commit, inventory and a selected skill in the initial catalogue, then apply `$verification-before-completion` to the local inventory validator and report its actual exit code. If the skill is absent from the catalogue or the service profile still blocks startup, report that fact; do not call the fresh-session test passed.

Live databases, existing backups, secrets, external accounts, publication and deployment are outside startup scope. Do not open runtime data or run migrations. Local application changes, optional tools and logs from previous tasks are not proof of a reproducible remote checkout. Environment configuration requires the user's Review/Save and Publish; a saved draft is not active. Local-only commit restoration is not reliably supported by the current environment service, so do not claim fresh-task persistence without checking it.
