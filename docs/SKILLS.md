# Навыки EINEIRO

Реестр установленного набора — [skills-lock.json](skills-lock.json). Он фиксирует **33 локальных
навыка**, их источники, версии, полные SHA коммитов, лицензии и SHA-256 файлов. Исходники
upstream сохранены без правок вместе со справочниками и лицензиями. Правила адаптации к
EINEIRO находятся в `AGENTS.md` и этом документе. Установка не включает функции продукта
и не запускает внешние действия.

## Лицензии

MIT и Apache-2.0 разрешают коммерческое применение с соблюдением условий распространения.
Лицензии, авторские уведомления и применимые NOTICE сохранены. Для Apache нужно отмечать
изменения распространяемых файлов; текущие upstream-файлы не модифицированы. Права на
отдельные фото/шрифты и тарифы внешних сервисов проверяются отдельно.

У Sentry собственный `skills/sentry/LICENSE.txt` содержит Apache-2.0, а метаданные окружающего
плагина указывают MIT. Здесь сохранён отдельный навык с его собственным LICENSE.txt;
плагин целиком не копировался. Проектный навык миграций содержит оригинальные инструкции,
а не копии сторонних навыков; его `NOTICE.md` не назначает проекту стороннюю OSS-лицензию.

**Codex Security — отдельный управляемый плагин**, а не часть этих 33 каталогов.
В проверенном [manifest](https://github.com/openai/plugins/blob/0722921d5542fc593105c27bd52630babd8b8c2a/plugins/codex-security/.codex-plugin/plugin.json)
версии 0.1.32 указана лицензия `Proprietary`. Копирования его кода в репозиторий нет.
Официальный установщик вернул `user_confirmed=true`, `completed=false`: подключение
подтверждено, завершение/активация пока не подтверждены. Версия 0.1.32 — проверенная версия
источника, а не обещание версии, которую установит клиент. Сканирования не запускались.

## Применение вместе со Spec Kit

| Задача | Основной процесс | Дополнительные навыки / ограничение |
|---|---|---|
| Новая существенная механика | Spec Kit: specify → plan → tasks → analyze → implement → converge | TDD для поведения, подходящие предметные навыки, проверка перед итогом |
| Ошибка | Воспроизведение и systematic-debugging | Регрессионный тест, исправление причины, verification-before-completion |
| Дизайн | Существующее ТЗ и дизайн-навыки | Accessibility/performance и Playwright для подтверждения интерфейса |
| Маркетинг/SEO | `PRODUCT.md`, канонический документ и Silent Run addendum | Общий контекст, затем конкретный навык. Бюджеты, публикации и аккаунты не подключаются установкой |
| Миграция/restore | `eineiro-safe-migrations` в той же feature-спецификации | Подтверждённая цель → backup и restore → стенд → данные → rollback → проверки и снятие собственных пауз |

Приоритет: пользовательское задание и принятые ТЗ → правила EINEIRO и конституция →
текущая спецификация → рекомендации навыков. Примеры новых фреймворков, рекламных каналов,
отраслевых правил и показателей не заменяют продуктовые решения. Пользовательские данные
и существующий код нельзя удалять из-за общей формулировки TDD о начале заново.

Не запускайте все навыки подряд. Небольшие документальные/конфигурационные изменения
проверяются соразмерно; повторное разрешение на уже заданную работу не требуется.
Диагностика не должна выводить секреты, полные env, заголовки авторизации или DSN.
Реальные PostgreSQL, рекламные кабинеты, мониторинг и публикации требуют своего задания.

Известные необязательные локальные ссылки upstream:

- `ads/references/creative-research-automation.md` предлагает `competitor-profiling` и
  `customer-research`: они не установлены, эти ветви процесса не запускаются автоматически.
- `seo` и `accessibility` ссылаются на `web-quality-audit`: используйте установленные
  предметные навыки; полный оркестратор не требуется.
- Ссылки на пример `/features/analytics`, снимок `.playwright-cli/page-*.yml` и
  `settings-after.png` — примеры создаваемых ресурсов, а не отсутствующие зависимости.
- Sentry в upstream показывает путь из монорепозитория; локальный путь здесь:
  `.agents/skills/sentry/scripts/sentry_api.py`.

## Обнаружение и проверки

Рабочий каталог агента должен быть `/workspace/EP-Base` (или корень этого checkout на другой
машине). Навыки расположены непосредственно в `.agents/skills/<name>/SKILL.md`, с уникальными
именами и описаниями в YAML frontmatter. Читайте выбранный SKILL.md перед применением.
Уже открытый клиент может потребовать новую сессию для обновления своего списка.

```bash
python scripts/check-skills.py
PYTHONDONTWRITEBYTECODE=1 python scripts/check_skills_test.py
```

Первый скрипт проверяет реестр, файловую целостность, имена, пути, лицензии/NOTICE и точный
набор Superpowers без сети и БД. Он не имитирует загрузчик Codex. Второй проверяет реальные
отказы валидатора на изменённых/лишних файлах, дубликатах, неполном наборе и опасных путях.
Полный YAML дополнительно проверен при установке.

Штатная проверка Codex 0.159.2 останавливается до загрузки навыков: служебный профиль
`/run/codex-environment/codex-home` смонтирован read-only, и Codex не может создать отсутствующий
`installation_id`. Повторный запуск новой сессии также заблокирован. Это не результат PASS
для агентного загрузчика. [Настройка облачного запуска, доказательства, ограничения сохранения
локального commit и инструкция новой задачи](CLOUD_SKILLS.md). Проверка существующего набора
без установки: `bash scripts/cloud-skills-setup.sh`.

## Вспомогательные инструменты

В текущем workspace установлены Specify CLI 1.2.2 и Playwright CLI 0.1.22. Они не добавлены
в runtime-зависимости приложения. Следующая команда документирует закреплённую версию
для отдельной будущей задачи установки, если инструмент отсутствует; при подключении
навыков и в startup она **не выполняется**:

```bash
npm install --prefix /workspace/.tools/playwright --save-exact --ignore-scripts \
  --no-audit --no-fund --cache /workspace/.cache/npm @playwright/cli@0.1.22
NO_UPDATE_NOTIFIER=1 /workspace/.tools/playwright/node_modules/.bin/playwright-cli --version
```

Этот релиз CLI закрепляет `playwright` и `playwright-core` на
`1.64.0-alpha-1790635538000`; источник, версии и npm integrity записаны в реестре.
Для облачных вызовов используйте полный путь выше, отдельную именованную сессию, временный
профиль и writable XDG cache/config. Системный Chromium проверен на локальном HTTP-fixture;
изолированный контейнер требует `chromiumSandbox: false`. Не подключайтесь к личному браузеру
и не останавливайте чужие сессии командами `close-all`/`kill-all`.

Sentry helper использует стандартную библиотеку Python. `--help` проверен без токена и API.
Настройка реального аккаунта, секретов и чтение его событий не выполнялись.

## Обновление набора

Обновляйте выбранный источник явно: прочитайте изменения и лицензии, зафиксируйте полный
коммит, сохраните все нужные локальные справочники, обновите `skills-lock.json` и проверьте
инвентарь. Для прежних дизайн-навыков/Spec Kit также обновляются их специализированные lock
файлы. Исходники не переписывайте ради локальных предпочтений; адаптации держите в правилах.
При расширении процесса миграций увеличивайте версию проектного навыка и пересматривайте
его сценарии. Не превращайте предупреждение об отсутствии необязательного навыка в
автоматическую установку полного стороннего пакета.
